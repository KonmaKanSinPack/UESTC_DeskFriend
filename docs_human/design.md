# 设计愿景 —— 桌面 AI 伙伴「桃桃/糯糯」

> 面向人的思路版：为什么这样设计。无代码实现细节，技术事实以 `docs_agent/` 为权威。

## 一句话

一个常驻桌面的小生命：听得见你说话、看得见你的屏幕、记得住你们聊过的事，
用软软的声音回应你——而不是一个等你操作的窗口。

## 核心理念：像生命体一样分工（器官化）

整个系统按生物体的方式切分职责，三条铁律：

1. **大脑不碰身体**。大模型只负责"想"——输出想说的话或想做的事（意图），
   从不直接碰麦克风、扬声器、屏幕。就像你的意识不会亲手操控耳膜振动。
2. **器官不认识大脑**。耳朵（语音识别）、嘴（发声）、眼睛（截屏）、皮肤（贴图气泡）
   都是纯粹的物理层，不知道 LLM 的存在。这保证了每个器官可以独立测试、独立替换——
   换个语音引擎不用动对话逻辑，换个形象不用动听觉。
3. **脊髓编排一切**。主控中枢（spine）监听所有器官的信号，决定"要不要回应、
   怎么回应、回应时命令哪些器官"。跨器官的流程永远只在这里组装。

这个划分带来的直接收益：任何新功能动手前，先问"这段逻辑属于脑、器官还是脊髓"，
答案唯一,代码就不会长歪。

## 记忆哲学：像人一样分层遗忘

- **短期记忆**按"轮次"保留完整对话，而不是掐条数截断；
- 老对话不硬删，压缩成一段**滚动摘要**（像人对昨天的记忆：细节模糊但主题记得）；
- 关于"你这个人"的重要事实（名字、学校、下周三要交报告）单独落一张**事实表**，
  永不进入摘要压缩,每次对话都带在身上。
- 设计红线：记忆系统的任何故障都**绝不阻断对话**——忘事可以,装死不行。

## 交互取舍：宁可确定,不要聪明

语音打断（barge-in)曾尝试 WebRTC 回声消除做"随时插嘴",真机表现不稳定。
最终选择确定性的半双工方案：**句子播放中不监听,句与句之间开一扇监听窗**——
插嘴要等当前句读完,但每次插嘴必然生效、必然被听清。
牺牲一点流畅度,换取"它一定会理我"的信任感。

同理:屏幕观察只在"画面变化 + 冷却期满 + 用户久未说话"时才主动开口,
宁可安静,不可骚扰。

## 双后端:人格可以搬家

"脑子"是可插拔的:默认走 AstrBot(人格、记忆由那边统一管理),也可以直连
OpenAI 兼容接口用自建记忆。判定"这句话要不要回应"则永远走独立的小模型通道——
快速、免费、不占用主对话模型的额度。

## 非目标(明确不做)

- 不用 Rust 重写(Python 胶水层不是瓶颈,分发需求出现前不折腾)
- 不做多平台适配(当前 Windows 开发 + Linux Wayland 路径保留)
- 不上向量数据库(事实量小,全量注入;检索用 SQLite 自带的 FTS5 就够)
