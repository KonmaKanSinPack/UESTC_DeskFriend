# 2026-08-13 打断/回声状态机加固（Tier 1 + Tier 2）· 计划与规格

> 状态：已与用户 brainstorm 定稿并批准（2026-08-13）
> 来源：`/code-review`（max effort，2 独立 finder + 逐行核对）在 barge-in/回声代码定位 15 缺陷，
> 用户拍板本轮修 Tier 1（4）+ Tier 2 插嘴硬化（6），共 10 条。

## 一、背景与目标

「句间监听窗口」方案（无 AEC，半双工）真机仍**自打断 / 自回复 / 插嘴丢话**。code-review 关键新发现
（比原计划 3 个快修更严重）：**窗口期录音被当污染丢弃**——用户成功插嘴、桃桃停嘴，但用户那句话
永远到不了 Whisper，是「打断体验坏」的真正主因，纯逻辑 bug 不依赖 AEC。

预期：朗读中说话 → 当前句读完、窗口期 → **可靠打断且用户话被正确转写送脑**；兜底文案不发声；
余响不被当用户话；插嘴时序竞态收敛。

## 二、设计红线（用户强调 + ARCHITECTURE.md）

- **解耦**：器官单向只读依赖不变——耳只**读**嘴的 `speaking/window_open/playing`，绝不**命令**嘴；
  打断链路仍走 `耳 emit interrupt_requested → ui(主控) → mouth.interrupt`。
- **简洁**：每个新状态只有一个 owner；判定能抽纯函数就抽（照 `should_drop_echo`）。
- **可读**：不加特例补丁；在正确的深度修（污染判定改用精确"此刻在播"信号，而非粗粒度会话标志）。

## 三、10 条缺陷 → 5 组设计

### 组 A：窗口期录音丢话（#1）— owner: TTS `playing` 标志
`segment_contaminated` 想表达"录音是否叠着**真实播放**"，却用了 `mouth.busy`(=`_busy`)——整个
`_speak_sync` 恒 True，句间窗口播放已暂停但 busy 仍 True → 窗口录音首块即判污染 → 整段丢。
修法：TTS 后端加精确 `playing`（`sd.play` 前后翻转，句间/合成期 False），污染判定改读它。

```python
# tts.py：__init__ self._playing=False；播放处 True/False 包住 sd.play+sd.wait
@property
def playing(self) -> bool:
    return self._playing  # TTS ABC 抽象属性；DummyTTS 回退 self._busy


# mouth.py：@property playing → getattr(self.tts,"playing",self.tts.busy)（无 playing 后端兼容）
# listen.py:226：playing_flags.append(self.mouth.playing ...)（segment_contaminated 签名不变）
```

### 组 B：兜底文案发声 → 回声环（#2）— owner: `BackendResponse.answered`
桥超时兜底「（桃桃没有回应…）」(`astrbot.py:222`) 与真回复无区分被朗读 → 麦克风拾回。
修法：契约声明"是否真回复"，主控不朗读（气泡仍显示）。

```python
# backends/base.py
@dataclass
class BackendResponse:
    content: str
    tool_calls: list[ToolCall] = field(default_factory=list)
    answered: bool = True  # False=桥超时/断线兜底；默认 True → openai.py 零改动


# backends/astrbot.py:221  if not content: return BackendResponse(content="（桃桃没有回应…）", answered=False)
# ui.py do_response  show_bubble 后：if not response.answered: return（不朗读/不压缩/不抽取）
```

### 组 C：回声内容兜底竞态 + 余响尾巴（#3、#4）— owner: `Mouth._last_spoken`
`is_echo` 比 `tts.played_text`，而 `_speak_sync` 开头 `_played=""`——两次串行 speak 间，A 余响转写
到达时 `_played` 已被 B 清空 → `echo_like` 早退 False → 漏判。`TTS_ECHO_TAIL=0.3s` ≪ 实测余响 ~1.3s。
修法：回声参考移进 Mouth，speak 收尾快照已播文本（跨清空保留）；`is_echo` 双参考取较像者。

```python
# mouth.py：__init__ self._last_spoken=""
# speak() finally 内、sleep 前：self._last_spoken = self.tts.played_text or text
def is_echo(self, text):
    return echo_like(text, self.tts.played_text) or echo_like(text, self._last_spoken)


TTS_ECHO_TAIL = 0.8  # 0.3→0.8 覆盖大部分余响；剩余长尾由 race-free is_echo 兜底
```

### 组 D：插嘴时序竞态（#5、#6、#7、#8）
- **#8 stale event**：`_busy=True` 早于新建 `_stop_event` → interrupt 见 busy=True 读到旧事件。
  修法：`_stop_event` 建在 `_busy=True` **之前**（重排）。
- **#5 gap 不可中断**：`time.sleep` 打断后窗口留满 0.6s。修法：Mouth 持 `threading.Event _gap_abort`，
  `_sentence_gap` 用 `wait(timeout)` 可被唤醒；owner=Mouth，`mouth.interrupt` 置位（**耳不碰**），speak 开头 clear。
- **#6 冷却/latch 跨回复残留**：修法：耳测 `speaking` False→True 沿，清自身 `_interrupt_sent/冷却/活动度`（owner=listen）。
- **#7 末句竞态误报**：修法：末句播完即 `_played=text`，竞态窗口收窄。
- 顺带 DummyTTS 补 `sentence_done_callback` 属性，窗口机制可单测。

```python
# tts.py _speak_sync setup（顺序）：_played="";_speaking_text=text;_stop_event=Event();_busy=True
# tts.py 末句：if i==len(sentences) and not self._stop_event.is_set(): self._played=text
# mouth.py _sentence_gap：window_open=False→if _gap_abort.wait(GUARD):return→window_open=True→_gap_abort.wait(WINDOW)→False
# listen.py：if speaking and not self._prev_speaking: 清 _interrupt_sent/_interrupt_cooldown_until/_window_activity
```

### 组 E：事件循环阻塞 + 合成期门控（#9、#10）
- **#9 Qt 跨线程投递延迟**：`on_timer_trick`（每 10s）→ `vision.sudden_view()` → 同步 `ImageGrab.grab()`
  阻塞 qasync 循环 → `interrupt_requested` 槽延迟。修法（解耦治根，不动耳→嘴）：截屏丢 `to_thread`。
- **#10 合成期门控**：`speaking=True` 早于首句播放，合成期吃插嘴。本轮按边界可接受处理（SiliconFlow 仅 1~2s，
  且门控此期防复捕用户话尾；CosyVoice2 10~20s 属未完成后端非生产）——加注释，组 A 的 playing 已让此期录音不误判污染。
- 顺带 #11：空句列表早退防 `ThreadPoolExecutor(max_workers=0)` ValueError。

```python
# ui.py：await asyncio.to_thread(self.vision.sudden_view)（定时/do_response 视觉调用）
# vision.look_at_screen 内 sudden_view 同样 to_thread
# tts.py _speak_sync：if not sentences: return（早退）
```

### 核心代码介绍
- **playing vs busy（组A，本轮头号）**：`busy` = 整个 `_speak_sync` 会话（含句间窗口/合成期恒 True）；
  `playing` = 仅 `sd.play` 一句时 True。`segment_contaminated` 逻辑 `any(flags)` 不变，把喂入信号从
  `busy` 换成 `playing` 即自动只丢「录音跑进下一句播放」的真回声段，窗口期干净录音得以送脑。
- **is_echo 双参考（组C）**：`Mouth.speak` 在 finally 快照 `_last_spoken = tts.played_text or text`；
  `is_echo` = `echo_like(text, played_text) or echo_like(text, _last_spoken)`。后者跨下一次 speak 的
  `_played=""` 清空仍保留，堵住串行 speak 间的漏判竞态。
- **可中断 gap（组D）**：`_sentence_gap` 用 `_gap_abort.wait(timeout)` 取代 `time.sleep`；`interrupt()`
  置位 `_gap_abort`（唤醒卡在 gap 的后端线程，窗口立即关）。owner=Mouth，耳仍只 emit 信号不碰嘴。

### 遇到的问题与处理
- **torch DLL 偶发 WinError 1114**：`test_listen` 收集时 `import ctranslate2 → torch` 间歇性 DLL 初始化
  失败（环境问题，非本轮代码）。处理：重试即过；已确认全量多次 151 passed。
- **`Listen.__new__` 而非 `object.__new__`**：QObject 子类禁用 `object.__new__`（sip 报 not safe）；
  单测用 `Listen.__new__(Listen)` 绕过 `__init__`（不开麦克风/不加载模型）验证 `_window_tick` 清闩逻辑。
- **偏离 spec（YAGNI，已记）**：plan 提「顺带 DummyTTS 补 sentence_done_callback 属性」——实测窗口机制已由
  `test_mouth` 直接调 `mouth._sentence_gap()` 覆盖，且 Dummy 无真实播放不需要窗口，遂**不做**（避免无谓耦合）。
- ruff format 会格式化 md 内 python 代码块（沿用 2026-08-11 处理，直接 `ruff format` 该文件）。
