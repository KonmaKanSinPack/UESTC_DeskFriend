# 2026-08-13 打断/回声状态机加固（Tier 1 + Tier 2）· 计划与规格

> 状态：已与用户 brainstorm 定稿并批准（2026-08-13）
> 来源：`/code-review`（max effort，2 独立 finder + 逐行核对）在 barge-in/回声代码定位 15 缺陷，
> 用户拍板本轮修 Tier 1（4）+ Tier 2 插嘴硬化（6），共 10 条。

## 一、背景与目标

「句间监听窗口」方案（无 AEC，半双工）真机仍**自打断 / 自回复 / 插嘴丢话**。code-review 关键新发现
（比原计划 3 个快修更严重）：**窗口期录音被当污染丢弃**——用户成功插嘴、桃桃停嘴，但用户那句话
永远到不了 Whisper，是「打断体验坏」的真正主因，纯逻辑 bug 不依赖 AEC。

预期：朗读中说话 → 当前句读完、窗口期 → **可靠打断且用户话被正确转写送脑**；兜底文案不发声；
余响不被当用户话；插嘴时序竞态收敛。

## 二、设计红线（用户强调 + ARCHITECTURE.md）

- **解耦**：器官单向只读依赖不变——耳只**读**嘴的 `speaking/window_open/playing`，绝不**命令**嘴；
  打断链路仍走 `耳 emit interrupt_requested → ui(主控) → mouth.interrupt`。
- **简洁**：每个新状态只有一个 owner；判定能抽纯函数就抽（照 `should_drop_echo`）。
- **可读**：不加特例补丁；在正确的深度修（污染判定改用精确"此刻在播"信号，而非粗粒度会话标志）。

## 三、10 条缺陷 → 5 组设计

### 组 A：窗口期录音丢话（#1）— owner: TTS `playing` 标志
`segment_contaminated` 想表达"录音是否叠着**真实播放**"，却用了 `mouth.busy`(=`_busy`)——整个
`_speak_sync` 恒 True，句间窗口播放已暂停但 busy 仍 True → 窗口录音首块即判污染 → 整段丢。
修法：TTS 后端加精确 `playing`（`sd.play` 前后翻转，句间/合成期 False），污染判定改读它。

```python
# tts.py：__init__ self._playing=False；播放处 True/False 包住 sd.play+sd.wait
@property
def playing(self) -> bool:
    return self._playing  # TTS ABC 抽象属性；DummyTTS 回退 self._busy


# mouth.py：@property playing → getattr(self.tts,"playing",self.tts.busy)（无 playing 后端兼容）
# listen.py:226：playing_flags.append(self.mouth.playing ...)（segment_contaminated 签名不变）
```

### 组 B：兜底文案发声 → 回声环（#2）— owner: `BackendResponse.answered`
桥超时兜底「（桃桃没有回应…）」(`astrbot.py:222`) 与真回复无区分被朗读 → 麦克风拾回。
修法：契约声明"是否真回复"，主控不朗读（气泡仍显示）。

```python
# backends/base.py
@dataclass
class BackendResponse:
    content: str
    tool_calls: list[ToolCall] = field(default_factory=list)
    answered: bool = True  # False=桥超时/断线兜底；默认 True → openai.py 零改动


# backends/astrbot.py:221  if not content: return BackendResponse(content="（桃桃没有回应…）", answered=False)
# ui.py do_response  show_bubble 后：if not response.answered: return（不朗读/不压缩/不抽取）
```

### 组 C：回声内容兜底竞态 + 余响尾巴（#3、#4）— owner: `Mouth._last_spoken`
`is_echo` 比 `tts.played_text`，而 `_speak_sync` 开头 `_played=""`——两次串行 speak 间，A 余响转写
到达时 `_played` 已被 B 清空 → `echo_like` 早退 False → 漏判。`TTS_ECHO_TAIL=0.3s` ≪ 实测余响 ~1.3s。
修法：回声参考移进 Mouth，speak 收尾快照已播文本（跨清空保留）；`is_echo` 双参考取较像者。

```python
# mouth.py：__init__ self._last_spoken=""
# speak() finally 内、sleep 前：self._last_spoken = self.tts.played_text or text
def is_echo(self, text):
    return echo_like(text, self.tts.played_text) or echo_like(text, self._last_spoken)


TTS_ECHO_TAIL = 0.8  # 0.3→0.8 覆盖大部分余响；剩余长尾由 race-free is_echo 兜底
```

### 组 D：插嘴时序竞态（#5、#6、#7、#8）
- **#8 stale event**：`_busy=True` 早于新建 `_stop_event` → interrupt 见 busy=True 读到旧事件。
  修法：`_stop_event` 建在 `_busy=True` **之前**（重排）。
- **#5 gap 不可中断**：`time.sleep` 打断后窗口留满 0.6s。修法：Mouth 持 `threading.Event _gap_abort`，
  `_sentence_gap` 用 `wait(timeout)` 可被唤醒；owner=Mouth，`mouth.interrupt` 置位（**耳不碰**），speak 开头 clear。
- **#6 冷却/latch 跨回复残留**：修法：耳测 `speaking` False→True 沿，清自身 `_interrupt_sent/冷却/活动度`（owner=listen）。
- **#7 末句竞态误报**：修法：末句播完即 `_played=text`，竞态窗口收窄。
- 顺带 DummyTTS 补 `sentence_done_callback` 属性，窗口机制可单测。

```python
# tts.py _speak_sync setup（顺序）：_played="";_speaking_text=text;_stop_event=Event();_busy=True
# tts.py 末句：if i==len(sentences) and not self._stop_event.is_set(): self._played=text
```

### 组 E：事件循环阻塞 + 合成期门控（#9、#10）

### 核心代码介绍
- **playing vs busy（组A，本轮头号）**：`busy` = 整个 `_speak_sync` 会话（含句间窗口/合成期恒 True）；
  `playing` = 仅 `sd.play` 一句时 True。`segment_contaminated` 逻辑 `any(flags)` 不变，把喂入信号从
  `busy` 换成 `playing` 即自动只丢「录音跑进下一句播放」的真回声段，窗口期干净录音得以送脑。
- **is_echo 双参考（组C）**：`Mouth.speak` 在 finally 快照 `_last_spoken = tts.played_text or text`；
  `is_echo` = `echo_like(text, played_text) or echo_like(text, _last_spoken)`。后者跨下一次 speak 的
  `_played=""` 清空仍保留，堵住串行 speak 间的漏判竞态。
- **可中断 gap（组D）**：`_sentence_gap` 用 `_gap_abort.wait(timeout)` 取代 `time.sleep`；`interrupt()`
  置位 `_gap_abort`（唤醒卡在 gap 的后端线程，窗口立即关）。owner=Mouth，耳仍只 emit 信号不碰嘴。

## 二、模块设计

### 2.1 skin.py — Skin(QWidget)，外观器官（纯物理层）

从 ui.py 搬走（逻辑零改动）：窗口三件套（无边框/置顶/透明）、`_load_sprite`
（PNG/GIF）、气泡 QLabel + 自动隐藏定时器、输入框 + Esc 过滤、QVBoxLayout、
25fps 动画定时器 + `_anim_tick`、拖拽/单击/双击、`_just_double_clicked` 防误触。

对外接口（器官边界）：

```python
class Skin(QWidget):
    # —— 信号（广播输入；skin 不知道谁会来听）——
    text_submitted = pyqtSignal(str)   # 回车发送的文字（空文本 strip 后不发）
    touched = pyqtSignal()             # 双击"触碰"彩蛋

    # —— 命令（被主控命令；skin 不知道命令来自谁）——
    def show_bubble(self, text, timeout_ms=10000) -> None
        # 显示气泡；超时自动隐藏（skin 内部定时器），隐藏时自动复位 anim=idle
    def hide_bubble(self) -> None
    def set_anim_state(self, state) -> None   # "idle"/"thinking"/"talking" 语义级命令
```

关键点：

- **双击不再直接碰消息队列**（现 ui.py:312 是 `put_nowait`）——改为发 `touched()`
  信号，由 spine 决定入队什么（器官永远广播，主控决定用不用）。
- `set_anim_state` 是语义级命令（"表达正在思考"），渲染方式（今天整窗晃动、未来
  Live2D）是 skin 内部细节。
- skin 不 import brain / 不认识任何器官与 LLM。✓ 硬规则

### 2.2 spine.py — Spine，主控中枢（plain class，非 QObject）

从 ui.py 搬走（逻辑零改动）：器官装配与接线、消息队列 + 消费者合并积压、
`should_reply`、`do_response`、`tool_executer`、`_interrupt_tts/_async`、
`on_heard_text`、文字/触碰入队处理、`is_busy`。

```python
class Spine:
    def __init__(self, face=None, config=None, brain=None, vision=None, listen=None, mouth=None):
        # 全部可注入（测试）；生产路径默认装配（照 Brain(backend=None)/Mouth(tts=None) 模式）
        self.face = face or Skin()
        config = config or load_config()
        self.brain = brain or Brain()
        self.vision = vision or Vision()
        self.listen = listen or Listen()
        self.mouth = mouth or Mouth(config)
        self.message_queue = asyncio.Queue(maxsize=20)
        self.is_busy = False
        # —— 接线（"中枢神经"的本体）——
        self.listen.mouth = self.mouth  # 耳单向只读嘴（不变）
        self.listen.interrupt_requested.connect(self._interrupt_tts)
        self.listen.text_signal.connect(self.on_heard_text)  # 普通方法内 create_task（见下）
        self.face.text_submitted.connect(self._on_text_submitted)
        self.face.touched.connect(self._on_touched)
        self.brain.reply_sink = self._on_proactive_bubble  # 主动冒泡 → face.show_bubble

    def start(self):
        # 消费者任务从 __init__ 移到这里：构造不依赖活着的 loop → test_spine 无 loop 即可实例化
        asyncio.get_event_loop().create_task(self.on_received_message_consumer())

    def on_heard_text(self, text):
        # 不用 @qasync.asyncSlot（spine 是 plain class，不沾 Qt）——照 _interrupt_tts 的
        # create_task 模式把协程挂到 loop；pyqtSignal 连普通 callable 即可
        asyncio.get_event_loop().create_task(self._on_heard_text(text))
```

选 plain class 而非 QObject 的理由：spine 不发任何信号（只命令器官、订阅信号），
`signal.connect()` 接受任意可调用对象；同理协程槽不用 `@qasync.asyncSlot`（Qt 槽机制），
改普通方法内 `create_task`——spine 里零 Qt 依赖。普通类让 test_spine.py 无需 QApplication、
无需活着的 loop 即可测全部编排逻辑——这是拆分的核心收益。

### 2.3 main.py 装配

```python
# onnxruntime 先行 / SIG_DFL / QApplication 不变
loop = qasync.QEventLoop(app)
asyncio.set_event_loop(loop)

spine = Spine()  # 内部装配器官 + face（可注入）；时序同现状（loop 已 set 未 run）
spine.start()  # 起消费者任务（与构造分离，便于 test_spine 无 loop 实例化）
spine.face.show()

with loop:
    loop.run_forever()
```

`current_loop()` 无需改动（构造仍在 `run_forever()` 之前，回退分支生效）。

## 三、数据流（拆分后，与现状一一对应）

```
耳线程 → text_signal → spine.on_heard_text
  → is_echo 过滤 → _interrupt_tts → face.set_anim_state("thinking")
  → face.show_bubble("听到了，正在想…", 60000) → 入队
消费者（合并积压）→ should_reply
  → true：do_response → brain → face.show_bubble(回复) + set_anim_state("talking")
           + mouth.speak 异步 + maybe_compress/maybe_extract_facts
  → false：brain.memorize + face.hide_bubble
  → answered=False：只 show_bubble 不朗读（组B 逻辑原样搬）
文字：face.text_submitted → spine._on_text_submitted（打断 + 气泡 + 入队，现状逻辑）
彩蛋：face.touched → spine._on_touched → 入队"用户用鼠标触碰了你"
插嘴：listen.interrupt_requested → spine._interrupt_tts → mouth.interrupt → 前缀注入
冒泡：brain.reply_sink = spine._on_proactive_bubble → face.show_bubble(text)
气泡超时：skin 内部 hide_bubble → 自动复位 idle（spine 不参与）
```

边界处理全部照搬现状：队列满丢弃、should_reply 异常判 false、do_response 异常
hide_bubble、finally 释放 is_busy、空文本不发信号、Esc/拖动/单击切换 skin 内部消化。
