# 2026-08-10 桌宠接入 AstrBot（C方案）· 计划与规格

> 状态：已与用户 brainstorm 定稿（2026-08-10）

## 一、目标

桌宠的"脑子"从"自己调 LLM"换成可插拔后端，本次实现两种：

- **astrbot 后端**（默认）：走 OneBot 11 伪装通道接入 AstrBot 的桃桃（记忆/人格由 AstrBot 接管）
- **openai 后端**（可选）：原直连 LLM + 自建记忆（Phase 5/6 系统保留），作为对照与回退

**深度解耦**：brain 定义统一契约（5 个接口 + 响应对象），后端按 `config.toml` 的 `BACKEND` 键选择，`create_backend()` 工厂装配。

## 三、关键接口设计

### 1. backends/base.py —— 统一契约

```python
@dataclass
class ToolCall:
    id: str
    name: str
    arguments: str  # JSON 字符串


@dataclass
class BackendResponse:
    content: str  # 最终回复文本（ui 直接显示）
    tool_calls: list[ToolCall]  # openai 后端有值 → ui 走工具循环；astrbot 后端恒空


class ReplyBackend(ABC):
    name: str

    async def get_llm_response(self, message, model=None) -> BackendResponse:
        """对话：message 为 str（新轮次）/ dict / list[dict]（按序追加），返回回复。"""

    async def get_response_with_context(self, context, model=None, use_tools=False) -> BackendResponse:
        """should_reply 判定：返回 content="true"/"false"。"""

    def memorize(self, message): ...  # 背景谈话只记不答
    async def maybe_compress(self): ...  # 记忆压缩（超限时）
    async def maybe_extract_facts(self): ...  # 事实抽取
```

> **为什么这样归一**：旧 ui 直接读 OpenAI SDK 响应（`.choices[0].message`），SDK 类型泄漏进契约。
> 归一为 `BackendResponse` 后 ui 只认 content/tool_calls，双后端实现互不可见。代价：ui.py 约 15 行适配。

### 2. onebot_bridge.py —— OneBot 11 伪装客户端（astrbot 后端专用通信层）

```python
class OneBotBridge:
    def __init__(self, url, token="", self_id=10001, user_id=1063310598,
                 nickname="老公", timeout=90.0, settle=2.0):
        ...

    def start(self):                 # 常驻连接循环：反向WS + Bearer token + 指数退避重连(1→30s)
    async def ensure_connected(self):  # 等连接就绪（5s 上限），失败抛 ConnectionError
    async def send_message(self, segments: list[dict]) -> str:
        """发 message 事件 → 等桃桃回复（静默窗口取最后一条）→ 返回回复文本。
        超时/断线返回 ""。"""
```

- **上行事件**：`post_type=message, message_type=private, sub_type=friend, user_id=1063310598,
  sender={user_id, nickname:"老公"}, message=[segments], raw_message, message_id=随机`
  - segments：text `{"type":"text","data":{"text":...}}`；image `{"type":"image","data":{"file":"base64://...","subType":0}}`
- **下行动作**：`send_private_msg`/`send_group_msg`/`send_msg` → 提取文本（str 或 segments 数组）→ 回复结算 → 回 `{status:ok, retcode:0, data:{message_id}, echo}`
  - `get_login_info` → 回 self_id（AstrBot 靠它识别 bot 身份）
  - 其余动作 → `ok + {}`（避免适配器报错重试）
- **心跳**：30s 一个 `meta_event(heartbeat)`；连接时发 `lifecycle/connect`
- **静默结算**：收到回复文本 → 取消旧结算任务 → `settle` 秒后无新回复则 resolve 为最新文本；总等待超 `timeout` 兜底
- **token**：`websockets.connect(extra_headers={"Authorization": f"Bearer {token}"})`（OneBot 11 规范；
  若联调 401 则改 `?access_token=`，已在文档标注）

### 3. backends/astrbot.py —— AstrBotBackend

```python
class AstrBotBackend(ReplyBackend):
    name = "astrbot"

    def __init__(self, url, token="", user_id=1063310598, self_id=10001, nickname="老公",
                 timeout=90.0, settle=2.0, screen_cfg=None):

        self.reply_sink = None          # ui 挂的主动冒泡回调（Brain 转发）
        self.bridge.start()             # 常驻重连
        self._observe_task = asyncio.create_task(self._observe_loop())  # 屏幕感知

        # 3) bridge.send_message() → 回复
        # 4) [look_at_screen] 协议：回复含标记 → 再截屏 → 附图追问（≤3 轮）→ 最终回复
        # 5) 超时/断线 → 兜底文案 "(桃桃没有回应…)"；标记文本从展示内容中剥离
        # 标记对话进行中 _active_until = now + 120s（状态机进入 active）

    async def get_response_with_context(self, context, model=None, use_tools=False):
        return BackendResponse(content="true" if should_reply_local(last_text) else "false")

    def memorize(self, message): ...            # 空操作：记忆由 AstrBot 接管
    async def maybe_compress(self): ...         # 空操作
    async def maybe_extract_facts(self): ...    # 空操作
```

**本地唤醒规则**（纯函数，可单测）：

```python
def should_reply_local(text: str) -> bool:
    # 触碰彩蛋: "鼠标"+"触碰" → True
    # 叫名字: 含 糯糯/桃桃 → True
    # 直接指令: 看看/屏幕/截图/打开/理我/出来/过来 → True
    # 问候: 你好/早安/午安/晚安/嗨/哈喽 → True
    # 疑问: ？/?/吗/什么/怎么/为什么/谁/哪/帮我/告诉 → True
    # 其余（背景碎片）→ False
```

**屏幕感知状态机**（用户想法 #1 + 成熟方案"事件驱动+变化门控+冷却"）：

```python
# ① 观察层：idle 态 60s / active 态 20s 截屏一张
# ② 门控层（全满足才动用桃桃）：
#    变化幅度 = phash(当前, 上次) > SCREEN_CHANGE_THRESHOLD(0.05)   # 16x16 感知哈希
#    距上次主动观察 > SCREEN_COOLDOWN(180s)
#    不在对话中（无在飞请求） 且  距上次用户消息 > SCREEN_USER_SILENCE(120s)
# ③ 行动层：发「(主动观察，没什么值得说的只回「无」) <截图>」
#    回复 ∈ {无/没有/不用/没什么/没啥/空} → 静默丢弃；否则 reply_sink(text) 主动冒泡
```

```python
def phash(img) -> int          # PIL resize(16,16) 灰度 → 256 位哈希
def phash_score(a, b) -> float # 归一化汉明距离 0~1
```

### 5. brain.py —— 门面（ui 契约不变）

```python
class Brain:
    def __init__(self, backend=None):        # ui.py 无参 → 读 config → create_backend()
        self.backend = backend or create_backend(load_config())

    @property
    def reply_sink(self):  # 转发给支持主动冒泡的后端（astrbot）

    @reply_sink.setter
    def reply_sink(self, fn): setattr(self.backend, "reply_sink", fn)

    # 5 个接口原样转发 backend
    async def get_llm_response(...) / get_response_with_context(...) / maybe_compress(...) / maybe_extract_facts(...)
    def memorize(...)
```

### 遇到的问题与处理

1. **websockets v17 参数名坑**：`extra_headers`（v14）在 v17 又改回 `additional_headers`；且请求头名被统一转小写（测试断言踩了 `Authorization` vs `authorization`）。→ 用 v17 API + 注释留档。
2. **桥测试假服务端过早断连**：handler 收到 lifecycle 事件就 return → 桥视为断线重连 → `ensure_connected` 超时。→ handler 跳过 meta 事件、保持连接存活。
3. **静默窗口语义自测纠偏**：间隔 > settle 时取第一条是**正确行为**（settle 就是干这个的）；补了"间隔超窗取早回复"的边界测试 + 文档说明调参含义。
4. **后台任务悬挂警告**：`get_event_loop().create_task` + 无停止入口 → 进程退出 "Task was destroyed"。→ 补 `async stop()`（取消+等待），统一 `get_running_loop()`；冒烟测试干净退出。
5. **phash 退化用例**：纯色图感知哈希恒为全 1（全等），测试用例本身错了。→ 换渐变图。
6. **⭐ AstrBot 握手 400 悬案（最大坑）**：探测矩阵显示 Bearer → 400、无头 → 401、查询参数全 401。装 aiocqhttp 库读源码（`_handle_wsr`）破案：token 正则校验通过后**还要 `X-Client-Role` 头**（event/api/universal 角色），缺了 KeyError → 400；`X-Self-ID` 决定动作路由。→ 补两个头，实测握手成功。
7. **端到端联调成功**：真实发消息 → 桃桃回复（认出"老公"，身份映射生效）。回复带 markdown → 新增 `clean_markdown` 剥符号（代码围栏/加粗/斜体/标题/行内代码）。

**问题**：`uv run python main.py` 启动即崩——`RuntimeError: no running event loop`（onebot_bridge.py 建后台任务处）。

**根因**：main.py 时序是「先 `DeskFriend()`（内部 `Brain()` → 后台任务）→ 后 `loop.run_forever()`」。
qasync 的 loop 已 `set_event_loop` 但**尚未运行**，`asyncio.get_running_loop()` 抛错。
上一轮把 `get_event_loop()` 统一替换为 `get_running_loop()` 时引入的回归（当时冒烟测试在运行中的
loop 内构造，掩盖了真实时序）。

**修复**：`onebot_bridge.current_loop()` 辅助——优先运行中的 loop，否则回退已设置的 loop
（qasync 场景）；`backends/astrbot.py` 同步使用。附带踩坑：sed 批量替换时把 `current_loop()`
函数**自身内部**的调用也替换了（无限递归），手动修正。

**验证**：模拟 main.py 时序（loop 已 set 未 run）构造 Brain → 成功且真实连上 AstrBot；
新增回归测试 `test_constructs_before_loop_running`（79 passed）。

### 追加：Splitter 插件"发送失败"修复（2026-08-10 晚）

**问题**：AstrBot 侧日志 `[astrbot_plugin_splitter.main:325] [Splitter] 发送失败`（时间戳恰逢
桌宠联调时段）。

**根因**：AstrBot 发送链路（aiocqhttp_message_event.py）对 `Node/Nodes`（合并转发）消息段
走 `send_private_forward_msg` / `send_group_forward_msg` 动作；桥此前把这类动作当"未知动作"
回空 `ok`，AstrBot 侧 `_handle_api_result` 拿不到规范要求的 `data.message_id` → 抛异常 →
Splitter 报"发送失败"。（Splitter 插件把桃桃长回复拆段打包成合并转发发送。）

**修复**（onebot_bridge.py）：按 OneBot 11 规范支持合并转发动作——
`extract_forward_nodes_text()` 把各 node 的文本段提取拼接（QQ 里是转发卡片，桌宠气泡只能
展示文本），进静默窗口结算显示；响应回 `{message_id}`。顺带发现测试时序竞态：
handler 收到 ok 响应就关连接 → 断线清理抢在静默窗口前把结果置空 → 测试需保持连接等结算。

**验证**：新增合并转发动作测试 + 提取函数用例，83 passed。

### 追加：唤醒判定器改造（治漏判，2026-08-10 晚）

**问题**：用户反馈"决策器老判断 false，我让他回复都不回"。澄清一个误区：ui.py 的
should_reply() 两个模式都走，但 **astrbot 后端忽略 judge 提示词，只跑本地关键词规则**
（should_reply_local），"改提示词"对 astrbot 模式无效。

**改动**（backends/astrbot.py）：
- should_reply_local 从"保守名单、默认 false"改为**反向判定**：空文本/纯语气词碎片
  （BACKGROUND_NOISE 名单）→ false；名字/指令/疑问/问候/触碰 → true；**其余主动搭话默认 true**
- get_response_with_context 剥离 ui 固定的 "用户的消息是：" 前缀——否则纯语气词带前缀
  不命中名单，背景碎片也会误触发（测试暴露的真实 bug）
- docs/DEVELOPMENT.md §7.3 唤醒规则同步更新

**验证**：新增 test_active_talk_default_reply（"陪我玩""讲个笑话"等必回），84 passed。
**权衡**：背景谈话（跟别人聊天）偶尔会误触发回复，观察后可按需加反向名单。
