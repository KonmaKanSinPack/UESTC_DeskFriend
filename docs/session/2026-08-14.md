# 2026-08-14 openai 判定通道独立化（对话 MiniMax + 判定本地 qwen）

## 背景

openai 模式真机测试（昨日）暴露：判定与对话共用主 client，每次说话先打一次 MiniMax。
用户配置意图明确（config 里加了 `JUDGE_URL` 指向本地 LM Studio）：**对话走 MiniMax-M3，
判定走本地 qwen3-1.7b（免费、快、不占主模型额度）**。初版只改了 `create_judge` 读
`JUDGE_URL`，但 openai 分支根本不调用 create_judge——判定仍在主 client。

## 文件改动（每个文件 → 改动 → 为什么）

| 文件 | 改动 | 为什么 |
|---|---|---|
| `backends/openai.py` | `__init__` +`judge` 参数（可注入），生产经 `create_judge(config)` 惰性构建；`get_response_with_context` 顶部加判定路由：上下文首条 system == `JUDGE_SYSTEM_PROMPT` → `judge.should_reply(_extract_judge_text(context))` | 判定通道独立化：不进主对话流、不占主模型额度；未配置判定器回退主 client（旧行为） |
| `backends/judger.py` | `_extract_judge_text` 从 astrbot.py 迁入（docstring 同步 spine 措辞） | 双后端共享，避免 openai→astrbot 互相引用（破坏解耦约定） |
| `backends/astrbot.py` | 删除本地 `_extract_judge_text`，改 `from .judger import` | 单一来源 |
| `backends/__init__.py` | `create_judge`：`JUDGE_URL` 优先、缺则回退 `BASE_URL`（旧行为兼容）；docstring/报错信息同步 | 老配置不破坏 |
| `config.example.toml` | 判定器段补 `JUDGE_URL` 说明 | 配置自文档化 |
| `tests/test_judger.py` | +3：extract 剥前缀/无前缀直通/空上下文 | 迁移函数回归保护 |
| `tests/test_memory.py` | +3（TestJudgeChannel）：判定上下文路由到 judge（剥前缀断言）/ 记忆上下文不匹配走主 client / judge=false 返回 "false" | 路由判别回归保护 |
| `docs/DEVELOPMENT.md` | §7.3 should_reply 小节：openai 后端判定通道更新（2026-08-14 起） | 决策留档 |

## 核心代码介绍

- **提示词身份路由**：`get_response_with_context` 同时服务判定与记忆系统（摘要压缩/
  事实抽取/合并）。判定上下文的首条 system 恒为 `JUDGE_SYSTEM_PROMPT`（spine 构造，
  单一来源），记忆上下文各有自己的提示词——按提示词身份判别，避免把记忆链路误路由
  到判定器（若全路由，摘要压缩会收到 true/false 当摘要）。
- **惰性导入**：`from . import create_judge` 在 `__init__` 内——openai.py 由
  create_backend 分支加载，彼时 create_judge 已定义，无循环导入。
