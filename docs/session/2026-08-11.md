# 2026-08-11 TTS 方案定型：SiliconFlow API 转正，本地 CosyVoice2 标记未完成

## 背景
本地 CosyVoice2（昨天接入）合成乱码 + 速度不稳定（6.7s~386s/句）。

## 排查结论（根因）
- 现象：合成流程通但内容完全无关 + 音色不像（官方示例音频也乱）
- 排除：参考音频（换干净 5.9s + 精确转写）/ 模型文件完整性 / whisper 版本（20231117）/
  fp16（官方环境 fp16=True 正常）
- 根因：**版本栈整体漂移**——主环境 Python 3.12 + torch 2.11 + onnxruntime 1.24 + numpy 2.x
  与官方矩阵（3.10 + torch 2.3.1 + onnxruntime 1.18 + numpy 1.26 + whisper 20231117 +
  transformers 4.51.3 + x-transformers 2.11.24）数值行为不同 → speech token 全错
- 单点降级不可行：transformers 5.x 要 torch 2.4+（register_fake）、x-transformers 2.25 要
  torch 2.5+、torch 2.3.1 + transformers 4.51.3 又缺 register_fake——互相锁定
- 官方环境（.venv-cosyvoice，Python 3.10 + requirements 全量）验证**正常**，但速度仍不稳
  （195s~386s 复现），且需独立环境常驻

## 决策（用户拍板）
放弃本地方案作为主路径，改用 **SiliconFlow API**（官方托管 CosyVoice2-0.5B）：
- POST /v1/audio/speech，`references` 参数每次传参考音频 base64 + 文本 → 零样本克隆
- response_format=wav 直接 sounddevice 播放；1.6s/句稳定
- 音色验证：胡桃参考音频克隆效果满意

## 改动
- `tts.py`：新增 SiliconFlowTTS（逐句请求 + 播放 + 打断复用）；工厂加 siliconflow 分支；
  CosyVoice2TTS docstring 标记"⚠️ 未完成"（保留待完善：官方环境常驻服务 + vllm）

- `tests/test_tts.py`：SiliconFlowTTS 4 用例（references 请求构造、base64 缓存、缺配置容错）
- `.gitignore`：+`.venv-cosyvoice/` +`assets/models/`（3.3GB 模型不入库）
- 参考音频入库：assets/vo_hutao_mimitomo_friendship2_01.wav（桃桃音色资产）

## 修复：桃桃说话会自己打断自己（回声回环）

### 现象
桃桃朗读时突然中断，并可能对自己的声音又回复（自反馈循环）。

### 根因（已排查）
麦克风永久监听（listen.py 守护线程，VAD+Whisper），**没有"桃桃正在说话"的感知**：
桃桃朗读 → 扬声器放声 → 麦克风拾回 → VAD 触发 → Whisper 转写（转写出的就是桃桃自己的话）
→ `on_heard_text` → `_interrupt_tts()` **打断自己** → 回声文本入队 → should_reply 判 true → 再回复 → 再被打断……自反馈回环。
打断入口只有 `on_input_submitted`（打字）与 `on_heard_text`（听到语音），打字排除 → 唯一可疑入口即麦克风回声。

### 方案（用户拍板：方案 A 本轮，AEC 回声消除下轮）
**TTS 播放期间（含 0.3s 余响尾巴）麦克风拾到的语音一律视为回声丢弃**；
说话期间语音插嘴失效（可打字打断），后续 AEC3（pywebrtc-audio）上线后恢复插嘴并把门控作为 AEC 收敛期兜底。

### 涉及文件
- `listen.py`：`Listen.speaking` 标志 + VAD 触发点回声忽略 + 录音段污染标记
- `ui.py`：speak 前置位/结束释放门控（`_speak_then_release` 封装，try/finally 保证释放）
- `tts.py`：interrupt 竞态修复（播完瞬间不误报打断位置）
- `tests/test_tts.py` + `tests/test_listen.py`（新增）：单测

**② ui.py — 门控置位/释放（余响尾巴）**

```python
TTS_ECHO_TAIL = 0.3  # 播完后的扬声器余响尾巴（秒），期间拾音仍视为回声


def do_response(self, message):
    ...
    self.listen.speaking = True  # speak 任务启动前置位（覆盖合成+播放全段）
    asyncio.get_event_loop().create_task(self._speak_then_release(response.content))


async def _speak_then_release(self, text):
    try:
        await self.tts.speak(text)  # 可被打字打断（interrupt 提前返回也走 finally）
    finally:
        await asyncio.sleep(TTS_ECHO_TAIL)
        self.listen.speaking = False  # 无论如何释放，防止门控卡死
```

**③ tts.py — interrupt 竞态修复**

竞态：最后一句播完、`finally: busy=False` 之前 interrupt() 被调用 → 返回**完整文本**当打断位置误注入。
修复：`_speak_sync` 记录本次朗读全文 `self._speaking_text`；interrupt 返回前比对——前缀==全文说明没真打断 → 返回空串。

```python
def _speak_sync(self, text):
    ...
    self._speaking_text = text
    ...

async def interrupt(self) -> str:
    if self._busy and self._stop_event is not None:
        self._stop_event.set()
        ...sd.stop()...
    prefix, self._played = self._played, ""
    if prefix == self._speaking_text:   # 完整播完，非打断 → 不误报
        return ""
    return prefix
```

### 核心代码介绍
- **门控主链路**：`during_listening` 外层 VAD 触发 → `is_echo_trigger(score, self.speaking)` 命中 → 忽略（不 reset VAD、不录音，读流保持同步）；录音循环内 `speaking_flags.append(self.speaking)` → 结束 `segment_contaminated` 命中 → 弃段。两处打印日志（"检测到 TTS 播放回声，忽略" / "录音段叠着 TTS 播放，丢弃"）供真机验证。
- **置位/释放**：`ui.do_response` 在创建 speak 任务前置位；`_speak_then_release` 收尾（await speak → sleep 0.3 → 释放），被 interrupt 提前返回也走 finally。
- **interrupt 竞态**：`_speak_sync` 置 `_speaking_text`；interrupt 里 `prefix == _speaking_text` 判"完整播完"返回空——打断成立的前提是循环被 stop_event 截断（此时 `_played` 不会等于全文），比对逻辑自洽。

### 遇到的问题与处理
- ruff format 会把 md 里 python 代码块一起格式化（对齐空格）→ 直接 `ruff format` 该文件，与仓库规范一致。
- `echo_ignored` 去重：VAD 每 32ms 打一次分，若不防重会在整段朗读期间刷屏 → 首次进入回声忽略态才打印一次。
