```python
# skin.py —— 信号与菜单(器官只广播)
quit_requested = pyqtSignal()   # 托盘/右键「退出」→ 主控编排收摊

def _init_tray(self):
    self.tray = QSystemTrayIcon(self._tray_icon(), self)
    self.tray.setToolTip("桃桃 (UESTC_DeskFriend)")
    menu = QMenu(self)  # 父对象防 GC;triggered 带 checked 参数,用 lambda 桥到无参 emit
    menu.addAction("退出").triggered.connect(lambda: self.quit_requested.emit())
    self.tray.setContextMenu(menu)
    if QSystemTrayIcon.isSystemTrayAvailable():
        self.tray.show()   # 精简环境无托盘时跳过,右键菜单兜底

def contextMenuEvent(self, event):
    menu = QMenu(self)
    menu.addAction("退出").triggered.connect(lambda: self.quit_requested.emit())
    menu.exec_(event.globalPos())

# spine.py —— 编排(幂等闩,顺序=资源依赖序)
def __init__(self, ..., quit_app=None):
    self._quit_app = quit_app       # main 注入 app.quit;spine 不 import Qt
    self._shutting_down = False
    self.face.quit_requested.connect(self._on_quit_requested)

async def _shutdown(self):
    if self._shutting_down:
        return
    self._shutting_down = True
    await self.brain.stop()   # 桥结算在飞请求/观察循环取消(已有,幂等)
    await self.mouth.stop()   # 停在播朗读 + TTS 释放
    if self._quit_app:
        self._quit_app()

# mouth.py —— 器官命令
async def stop(self):
    await self.interrupt()    # 空闲时安全(后端有 if _busy 守卫);置 _gap_abort 关窗口
    await self.tts.close()    # 释放钩子(ABC 默认空操作)

# main.py —— 装配桥接(Qt↔spine 唯一交点)
spine = Spine(face=face, quit_app=app.quit)
```

- **退出信号流**:托盘菜单/右键菜单「退出」→ 皮 `quit_requested`(广播)→

# 2026-09-03 会话(第二轮):回复流程统一——主动观察并入主消息流

## Plan + Spec(已与用户确认)

### 背景

用户指出:代码应统一复用,主动观察的后续响应应走与文字/听力**一模一样的调用**;
此前所述"污染"问题本质是队列缺分流,应在发给 LLM 前用消息等待队列解决。
现状是两条响应路径(用户消息走 do_response;主动观察走 reply_sink 旁路只冒泡)。

### 已确认决策

1. **完全统一**:主动观察消息入主队列(source=proactive),响应走 do_response 全程
  (should_reply 例外:proactive 源跳过——四重门控已在后端做过,"要不要问"已决策)
2. **仅活跃期朗读**(用户选定):主动观察有话时,用户 2 分钟内交互过(ACTIVE_AFTER_CHAT
  时间窗)才朗读,空闲期只冒泡——门在后端时间窗上,经 `BackendResponse.speak` 标志传递,
  呈现代码单一路径只多一个条件

### 设计

```
耳/皮(源=user) ──────────┐
                          ├→ queue[(source, text)] → consumer → group_pending
后端主动观察(源=proactive)┘   (连续 user 合并"\n",proactive 独立成条)
                                 ├ user:      should_reply → do_response / memorize
                                 └ proactive: 直接 do_response
do_response:空 content → 完全静默;否则 talking+气泡;answered 门不变;新增 speak 门(朗读)
```

关键点(每条有代码依据):

1. **发起方向不破坏器官化**:backend 不认识 spine——照原 reply_sink 模式换方向正确的
   回调 `observe_sink`(Brain 门面 property → astrbot 属性);`_check_and_observe` 门控
   通过后调 `observe_sink(PROACTIVE_OBSERVE_TEXT)`,截图由 `get_llm_response` 的
   SCREEN_KEYWORDS 路径自动附图(文案本身含"屏幕/截图")。`reply_sink` 契约无消费者,删除。
2. **防污染=队列分流**:`group_pending` 纯函数——连续 user 源合并(语音碎片语义不变),
   proactive 独立成条按序处理;互斥由队列串行天然保证(原 bridge.busy 门控作用被取代)。
3. **"无话可说"语义**:astrbot 后端识别主动观察回复经 `_is_no_reply` 判"无"→返回
   `content=""`;`do_response` 空 content 直接 return(不气泡不朗读)。用户消息永不
   返回空(astrbot 有兜底文案),守卫只服务主动观察。
4. **自发消息不得污染三个状态**(get_llm_response 识别 `PROACTIVE_MARKER` 前缀分支):
   ①不更新 `_last_user_at`/`_active_until`(否则"用户静默"门控失灵)②不消费打断
   标记 `interruption`(那是留给下一条用户消息的)③回复 speak 由时间窗判定。
