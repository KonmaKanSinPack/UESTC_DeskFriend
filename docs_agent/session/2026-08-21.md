### 核心内容介绍

- **双层体系落地**:`docs_agent/`(agent 权威层)与 `docs_human/`(人读层)各就各位,
  根部 `AGENTS.md`/`CLAUDE.md` 双入口等价且都指向 RULES 单一权威。
- **technical.md 骨架的写法**:不新造事实——契约/接口/数据结构全部从 DEVELOPMENT 已有
  描述与代码签名抽查(`grep "def \|@property\|@dataclass"`)提炼,接口名逐一存在性验证。
- **docs_human 提炼原则**:design.md 讲"为什么这样设计"(理念层),overall.md 讲"怎么运转
  + 决策理由"(全局层),两篇互相不重复、均指路 docs_agent 取精确事实。

### 遇到的问题与处理

- **git rename 检测**:docs_agent 两文件工作区为 CRLF,依赖 `core.autocrlf=true` 在 add 时
  归一为 LF,提交后与原 blob 100% 一致 → 8 个文件全部识别为 rename(历史可追溯)。
- **防误入库**:全程定点 `git add`,不用 `-A`——`assets/persona/taotao.md`(用户私人文件)
  与 `local.md` 保持 untracked。
- Windows 下 git 输出大量 "LF will be replaced by CRLF" warning,benign(autocrlf 正常行为)。
