## Plan + Spec(设计已经用户确认)

### 需求(用户原述)

1. AstrBot 侧插件:输入来自桌宠时注入 system prompt——桃桃只输出简短聊天文字,
   **禁止动作/神态描写**,禁 markdown;输入不来自桌宠(QQ/NapCat)则零侵入
2. 插件可调本项目的 tool(首工具 look_at_screen),**调用链与桌宠侧一致**(唯一分发点)

### 已核实的源码事实(AstrBot v4.27.2,本机 D:\Astrbot\AstrBot)

- `@on_llm_request(event, req)` 钩子可改 `req.system_prompt`(star_handler.py:433 官方示例)
- 适配器 `aiocqhttp_platform_adapter.py`:事件带 `self_id`(abm.self_id);插件可
  `adapter.bot.call_action(action=…, self_id=…)`,支持任意 action 名 + echo 回包
- 桌宠桥 `_reply` 已按 echo 回 action 响应(onebot_bridge.py)

### 设计(确认稿)

```
桃桃 tool call → 插件 FunctionTool.call()
  → adapter.bot.call_action("deskfriend_tool", {tool,args}, self_id=10001)  [传话]
  → onebot_bridge._handle 新分支 → bridge.tool_handler 回调               [传话]
  → AstrBotBackend.tool_sink(brain 门面转发)→ spine.execute_tool          [唯一分发点]
  → vision.look_at_screen()(眼睛器官,与 openai 后端同入口)
  → echo 回包 {status, text, image: data-url} → 插件存图 → 同会话下一个
    on_llm_request 注入 req.context(方案 A;context 图片格式核对不过则自动落 B)
```

- **风格注入**:`on_llm_request` 中按 `event.message_obj.self_id == pet_self_id`
  (插件配置,默认 10001)追加约束文案;追加不替换(人设在 AstrBot 人格里)
- **旧 [look_at_screen] 文本标记保留作回退**(插件未加载时兜底),稳定后删

### 关键实现发现(源码核对,推翻了 spec 里方案 A 的原路径)

- **on_llm_request 只在 agent 循环开始前发一次**(internal.py:269),工具轮后的
  LLM 调用不再触发——原"钩子注图"路线不成立
- **`FunctionTool.call(context: ContextWrapper, **kwargs)`**:工具直接拿到
  `context.messages`(runner 自动维护的轮内消息列表)——**同轮注图的官方数据面**,
  比钩子 hack 干净;`mark_as_temp()` 使截图只喂 provider 不落持久历史
- `ProviderRequest.image_urls` 是消息级注图口(供未来用),工具轮内不可达
- `ImageURLPart(image_url={"url": "data:...")` 官方支持 data-uri,免临时文件
